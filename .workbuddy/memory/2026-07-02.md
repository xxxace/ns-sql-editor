# 2026-07-02

## 登录账户联动功能 — 开发方案编写

- 基于 `登录账户和其它账户联动功能需求.txt` 和当前 ns-sql-editor 项目代码探索，输出了完整开发方案文档
- 方案文档: `登录账户和其它账户联动功能-开发方案.md`

### 关键决策（方案建议）

1. **架构选型**: 推荐「混合模式」— 独立 linkageStore + 嵌入主界面的 LinkagePanel，而非独立模块或全嵌入
2. **对比匹配**: 以 DSNAME 为主匹配键，DBQUERY hash 为辅助
3. **同步方向**: 仅单向（目标→主会话）
4. **并发方案**: 乐观锁+重试（前端），理想情况后端提供原子化接口
5. **UI 形态**: 侧边抽屉（复用 DraftDrawer 模式）

### 用户第一轮反馈（已全部确认）

1. 只有一个主登录，其它自己切换作为目标会话
2. 两边语句都列出，主会话缺失的灰色显示
3. 主界面不涉及会话切换，只绑定主会话；目标会话选择在弹窗内
4. DSNAME 同一页面下唯一，不需要 hash 辅助
5. 仅单向：目标→主会话
6. 差异语句可"从外部更新"(UPDATE)，覆盖主会话 DBQUERY/SORTBYCONTENT
7. DSSTMSEQ=语句序号, DSSTMTY=语句类型(=TABSEQ)
8. 保存用主会话登录信息，源数据字段复制
9. 不考虑并发，唯一约束兜底
10. DSNAME 为空标红色异常
11. 弹窗+全屏，组件可拆分(组件+弹窗/抽屉/嵌入)
12. 无批量上限
13. 未明确字段留空，同步复制源数据

### 方案文档更新至 v0.2

- 架构改为「组件+弹窗」：LinkageCore(核心组件) + LinkageDialog(弹窗容器)
- 主界面仅 SqlToolbar 加一个按钮，零侵入
- 新增 UPDATE 流程（差异语句"从外部更新"）
- 并发方案简化为不做处理

### 用户第二轮反馈（已全部确认）

1. 新增语句按钮放在 StatementList 刷新按钮左边
2. 主界面不新增会话选择功能，页面清单和语句清单只绑定主会话，切换只能通过现有"切换连接"
3. 新增语句弹窗：用户填写基本信息（DSNAME），不需要填 DBQUERY，创建成功后切换到该语句由用户编写 → 创建占位语句

### 用户第三轮反馈（Q1-Q9 全部确认）

1. Q1: UPDATE 覆盖 DBQUERY + SORTBYCONTENT + REF1（语句说明）
2. Q2: **左右双列对照**（非统一混排列表）。左=主会话清单，右=目标会话清单。DSNAME 空标红，不在对方列表标灰。上方双下拉（主页面+目标会话）
3. Q3: 锁定当前页面，主会话切换只能通过"切换连接"
4. Q4: 刷新前如有未保存变更→弹窗提示
5. Q5: DiffPanel 职责单一，仅对比展示，更新操作由外层 SyncActions 管理
6. Q6: 目标会话连接过期→**弹窗让用户点击刷新会话**（不是自动静默刷新，也不是报错让用户手动切）。主会话调现有 reconnect()，目标会话需新增 silentLogin()（不切换 authStore 状态）
   - 需新增: searchDataWithAuth() (api/nameson.ts) + silentLogin() (stores/auth.ts) + SessionExpiredDialog.vue
7. Q7: 行级标红+⚠异常图标，不阻止其他操作
8. Q8: 仅 DSNAME 必填，其余留空
9. Q9: 创建后自动解锁编辑器
