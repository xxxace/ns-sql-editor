## 连接编辑功能 + SQL Playground（用户拍板后一次落地）

### 需求 1：连接面板支持编辑登录信息
- **UI**：`EditAccountDialog.vue`（新建）——弹窗形态照 ConnectionTransferDialog（点按钮弹出），表单内容复用"新建连接"四字段。LoginDialog saved tab 每条连接加「编辑」按钮。
- **编排**：`auth.updateAccount(oldName, patch)`（auth.ts 新增）：
  - 密码语义：`password === undefined` 保留原密码；字符串直接覆盖（空串=清空）。UI 用「保留原密码」checkbox（默认勾选）表达，不用 placeholder 提示（审查发现的边界）。
  - 改名 = 先 saveAccount(新名) 成功后再 deleteAccount(旧名)，防中途失败丢数据。
  - 改名校验：目标名已存在 → 拒绝（防覆盖他人连接）。
  - 当前连接处理：serverUrl 或 user 变更 → logout() + 提示重连（旧 session 必然失效）；仅改连接名/密码 → 同步 currentName/currentUser/serverUrl，session 保留。

### 修复：lightningcss `:deep` 警告（既有问题，非本次引入）
- 根因：`linkage/LinkageDialog.vue` 的 `<style>` 块**缺 scoped**，`:deep(.el-icon)` 无法被 Vue 编译器替换，原样透传给 Vite 8 默认 lightningcss minifier 报警告（Vite 8.1.2 起默认用 lightningcss，旧版 esbuild 不报）。
- 修复：非 scoped 下 `:deep(x)` ≡ `x`，改 `.main-session-tag :deep(.el-icon)` → `.main-session-tag .el-icon`，行为零变化。全项目唯一非 scoped + `:deep` 处。
- 教训：Vite 8 + lightningcss 下，非 scoped style 里写 `:deep` 必报此警告；scoped 的 `:deep` 会被编译成 `[data-v-x]` 不受影响。
