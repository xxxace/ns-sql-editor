# 2026-08-18 工作日志

## Bug2（创建首条语句）真正根因修复：砍掉创建时的服务端序号查询
- 现象：语句清单为空时无法创建新语句；创建流程先发 `getMaxTabseq` → `SELECT ... FROM PRJOBJDS WHERE OBJECTID=... ORDER BY TABSEQ DESC`（用户贴出的那条 SQL），空表时该查询无意义且是阻断点。
- 根因：与同步路径（Bug1）同源——序号本可本地推算，却走服务端查询；空清单场景服务端无数据可查。
- 修复（最小、与同步路径对称）：
  - `src/api/statement.ts`：删除 `getMaxTabseq` + `MAXSEQ_SQL` 及 `searchData/generateWhere` 死引用；`createStatement` 签名新增必填 `nextSeq: number`（由调用方本地推算），移除 `try/catch` 查询块。
  - `src/components/NewStatementDialog.vue`：新增 `nextSeq` computed = 已加载 `editor.statements` 的 `max(tabseq)+1`，空→1；传给 `createStatement`。
- 约定（沉淀）：PRJOBJDS 的 TABSEQ 序号一律**本地从已加载清单推算**，不再查服务端；`api/` 纯逻辑层不依赖 store，序号由消费者（弹窗/store）算好传入。
- 验证：`npm run build` 通过（vue-tsc 0 错，仅 @vueuse/core 第三方 pure-annotation 告警，可忽略）。
